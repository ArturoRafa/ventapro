# 3. Decisiones por Módulo

## 3.1 Clientes (para fiado)

Se crea la entidad Cliente que no existía en el modelo de datos original.

| **Campo** | **Tipo** | **Requerido** | **Notas** |
| --- | --- | --- | --- |
| id | INT (PK) | Auto | Autoincremental |
| nombre | VARCHAR(100) | Sí | Nombre completo del cliente |
| telefono | VARCHAR(20) | Sí | Teléfono principal de contacto |
| telefono_alternativo | VARCHAR(20) | No | Segundo número de contacto |
| direccion | TEXT | No | Dirección física del cliente |

| --- | --- | --- | --- |

## 3.3 Control de Caja

Caja completa con configuración flexible según las decisiones del cliente:

**Monto inicial: **Opcional. La tabla de configuración tiene un flag requiere_monto_apertura. Si es false, el cajero puede abrir caja sin ingresar monto. Si es true, el campo es obligatorio.

**Cierre de caja: **Obligatorio. El cajero debe registrar el monto real contado. El sistema calcula la diferencia (sobrante/faltante) automáticamente.

**Precondición: **No se puede registrar ninguna venta sin una caja abierta para el día.

**Restricción: **No se puede abrir una nueva caja si ya existe una abierta.

Modelo de datos actualizado para caja:

| **Campo** | **Tipo** | **Notas** |
| --- | --- | --- |
| id | INT (PK) | Autoincremental |
| cajero_id | INT (FK) | Usuario que abrió la caja |
| monto_inicial | DECIMAL(12,2) | Nullable si requiere_monto_apertura=false |
| monto_cierre_real | DECIMAL(12,2) | Monto físico contado al cerrar |
| monto_cierre_sistema | DECIMAL(12,2) | Calculado: monto_inicial + ventas_efectivo |
| diferencia | DECIMAL(12,2) | real - sistema (positivo=sobrante, negativo=faltante) |
| estado | VARCHAR(10) | abierta / cerrada |
| fecha_apertura | TIMESTAMP | Momento de apertura |
| fecha_cierre | TIMESTAMP | Momento de cierre (null si abierta) |
| notas_cierre | TEXT | Observaciones opcionales del cajero al cerrar |

## 3.4 Impuestos

**Decisión: **0% en el MVP. No se calcula impuesto en ventas.

El campo impuesto_porcentaje existe en la configuración del negocio para activarlo en una futura iteración sin cambios de esquema. La lógica de cálculo se implementa pero se aplica con 0%.

## 3.5 Tipos de Producto

**Decisión: **Dos tipos desde el inicio.

| **Tipo** | **Valor en BD** | **Descuenta stock** | **Ejemplo** |
| --- | --- | --- | --- |
| Inventario | inventory | Sí — impide venta sin stock | Café molido, gaseosas, galletas |
| Comida | food | No — solo reportes de venta | Almuerzos, empanadas, hamburguesas |

Ambos tipos se venden desde el mismo POS. La diferencia es solo en la validación y descuento de stock.

## 3.6 Tickets

**Decisión: **HTML imprimible como formato principal, con opción de descarga PDF.

Se prioriza HTML porque funciona en cualquier dispositivo sin dependencias adicionales y permite impresión directa desde el navegador. pdf-lib se usa como opción secundaria para descargar.

## 3.7 Datos Iniciales (Seed)

Se crea un script de seed que:

**1. **Crea el usuario Admin por defecto (credenciales en variables de entorno).

**2. **Crea el registro de configuración del negocio con valores default.

**3. **Opcionalmente carga categorías y productos de ejemplo para desarrollo.

# 4. Modelo de Datos Completo (MVP)

Entidades finales incluyendo las decisiones tomadas. Los nombres de tablas y columnas están en español según las convenciones.

| **Tabla** | **Columnas clave** | **Relaciones** |
| --- | --- | --- |
| usuarios | id, nombre, email, password_hash, rol, estado, created_at | cajas, ventas |
| configuracion_negocio | id, nombre_negocio, moneda, impuesto_porcentaje, usa_fiado, requiere_monto_apertura | Ninguna (singleton) |
| productos | id, codigo, nombre, categoria, tipo (inventory/food), precio, stock, stock_minimo, estado, created_at | detalle_ventas |
| clientes | id, nombre, telefono, telefono_alternativo, direccion, estado, created_at | ventas, creditos, abonos |
| cajas | id, cajero_id, monto_inicial, monto_cierre_real, monto_cierre_sistema, diferencia, estado, fecha_apertura, fecha_cierre | ventas |
| ventas | id, caja_id, cliente_id (nullable), cajero_id, total, forma_pago, estado (paid/pending), created_at | detalle_ventas, creditos |
| detalle_ventas | id, venta_id, producto_id, cantidad, precio_unitario, subtotal | ventas, productos |
| creditos | id, cliente_id, venta_id, monto_total, saldo_pendiente, estado, created_at | clientes, ventas, abonos |
| abonos | id, credito_id, cliente_id, monto, fecha, notas | creditos, clientes |
